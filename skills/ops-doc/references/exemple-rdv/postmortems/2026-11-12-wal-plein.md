# Post-mortem 2026-11-12 : volume WAL presque plein, archivage S3 cassé

| | |
|---|---|
| **Date** | 2026-11-12 |
| **Durée de l'impact** | aucune indisponibilité ; **2 jours sans archivage WAL** (RPO dégradé) |
| **Sévérité** | SEV3 (pas d'impact utilisateur, mais un risque de perte de données) |
| **Détecté par** | alerte `PVCFillingUp` (volume WAL de `rdv-pg-1` à 85 %) |
| **Rédigé par** | Camille R. |

## Résumé
Pendant une rotation des clés S3, l'ancienne clé a été révoquée **avant** que la nouvelle soit déployée. L'archivage WAL a échoué pendant 2 jours sans qu'aucune alerte ne se déclenche. Le WAL s'est accumulé sur le disque jusqu'à 85 %, ce qui a enfin déclenché `PVCFillingUp`. Une fois la nouvelle clé déployée, le WAL s'est vidé en 10 minutes.

## Impact
- Aucun pour les utilisateurs.
- **Pendant 2 jours, un crash disque nous aurait fait perdre jusqu'à 2 jours de RDV.**

## Chronologie
| Heure | Événement |
|---|---|
| 10/11 09:15 | Création de la nouvelle clé S3, révocation de l'ancienne « pour ne pas oublier » |
| 10/11 09:16 | L'archivage commence à échouer (`AccessDenied`). **Aucune alerte.** |
| 10/11 03:00 → 12/11 03:00 | Les 2 backups quotidiens échouent. **Aucune alerte** (`CNPGBackupFailed` n'existait pas encore) |
| 12/11 08:40 | `PVCFillingUp` se déclenche : WAL à 85 % |
| 12/11 08:55 | Diagnostic : `Working WAL archiving: FAILING`, logs `AccessDenied` |
| 12/11 09:05 | Nouvelle clé chiffrée avec SOPS, MR, sync |
| 12/11 09:15 | Archivage OK, WAL vidé, backup manuel réussi |

## Cause racine
1. Pourquoi l'archivage a cassé ? → clé S3 révoquée.
2. Pourquoi révoquée trop tôt ? → pas de procédure de rotation, je l'ai fait de mémoire.
3. Pourquoi 2 jours sans le voir ? → **aucune alerte sur l'échec de backup ou d'archivage**, seulement sur le disque.

## Ce qui a bien marché
- Le WAL sur un volume séparé : les données n'ont jamais été menacées.
- `PVCFillingUp` sur une tendance (`predict_linear`) plutôt qu'un seuil fixe : elle s'est déclenchée avec de la marge.

## Ce qui a mal marché
- Aucune alerte directe sur les backups.
- Rotation faite sans procédure.

## Où on a eu de la chance
Aucun incident disque pendant ces 2 jours.
